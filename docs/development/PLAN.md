## Этапы

### Э0. Фундамент

Стек: Vue 3 + TypeScript + Vite (уже есть) + Tailwind CSS 4 + Pinia + Vue Router.
Библиотеки: `decimal.js` (точные суммы), `exceljs` (чтение/запись `.xlsx` в браузере),
`@vueuse/core`. Все зависимости — локальные, ни одного CDN (ТЗ 10.1).
Адрес API — из переменной окружения (ТЗ 10.2), хардкод — дефект.

### Э1. Дизайн-система и UX-карта

- Лена: нейтральные токены в `src/assets/ui.css` — серая шкала и один акцент
  (`--color-ui-accent`), статусы отдельными ролями (`--color-ui-danger` /
  `--color-ui-warn` / `--color-ui-success`), плоскости `--color-ui-page` /
  `--color-ui-surface` / `--color-ui-sheet`, системные шрифты,
  `tabular-nums` для всех сумм. Светлая и тёмная темы на одних и тех же ролях.
  Базовые компоненты: кнопка, поле, карточка, плашка, таблица, вкладки.
- Чиполлино: карта экранов, маршруты, чек-лист состояний каждого экрана,
  тексты всех сообщений об ошибках и пустых состояний.

### Э2. Ядро

- **Деньги.** Суммы приходят строками и через `parseFloat` не прогоняются никогда
  (ТЗ 5.3.1). Сравнение и сортировка — `decimal.js`, форматирование —
  `15 124 465,77` с неразрывным пробелом, ноль как `0,00` (ТЗ 5.3.2).
- **API-клиент.** `GET /orders`, `POST /report` (файл), `GET /health`.
  Таймаут расчёта ≥ 15 минут (ТЗ 7.1.1), без автоповторов (ТЗ 7.1.3).
- **Мок-слой** для нереализованных ручек (ТЗ 5.2): JSON-отчёт, фоновый режим,
  история, переопределение. Подмена мока на реальную ручку не переписывает экраны.
- **Словарь колонок** в одном месте: таблицы строятся по фактическому составу
  ключей `by_column`, а не по захардкоженному `CC/CD/CE` (ТЗ 5.2, критерий 11.9).
- **Единый шлюз тяжёлых запросов**: одновременно к сервису идёт не более одного
  тяжёлого запроса (ТЗ 7.1.4).

### Э3. Каркас и период

Шапка с текстовым логотипом «Факт», единый выбор периода, доступный с любого экрана
(ТЗ 9.1). Свободный ввод (`2026-06`, `июнь 2026`, `June 2026`), разбор — на
бэкенде (ТЗ 5.3.3). Индикатор доступности сервиса по `/health` и действующий
фильтр состава `orders_filter` (ТЗ 9.7). Переключатель темы
(система / светлая / тёмная) в шапке. Точка входа готова к тому, чтобы её
закрыли экраном логина без переработки навигации (ТЗ 10.3).

### Э4. С1 — Предпросмотр состава расчёта

Таблица заказов (номер, наименование, оборот, НЗП, «в работе», «попадёт в расчёт»),
сортировка по любой колонке, поиск, без пагинации. Счётчики. Заметный блок
предупреждений: `unmatched` и `turnover_without_order ≠ 0`.
«В работе» и «участвует в распределении 26 сч» не смешиваются (ТЗ 3).

### Э5. С2 — Запуск расчёта

Запуск с экрана предпросмотра тем же периодом. Предупреждение о длительности
до нажатия. Блокировка второго параллельного расчёта. Прогресс с объяснением
после 10 секунд. Скачивание файла с именем из `Content-Disposition`.
Результат остаётся на экране после скачивания.

### Э6. С3 — Результат на экране

Три представления одних данных: **Свод по заказам** (с раскрытием расшифровки
по клику и всегда видимой строкой итогов), **Распределение 26 счёта** (доли,
сумма долей = 100 %, база распределения), **Расшифровка** (фильтры по заказу,
колонке, счёту; поиск по статье). Отдельный блок — расшифровка 26 счёта
по статьям. Шапка липкая, итоги не под прокруткой (ТЗ 9).

### Э7. С4 — Несходимость и ошибки

Отдельный экран отказа по сверке: перечень непрошедших проверок
(название, ожидалось, получено, расхождение), следующий шаг, **без кнопки
принудительного скачивания**. Разные корректные сообщения для 400 / 422 / 500 /
502 / 504 / «сервис недоступен» (ТЗ 8). Техника — в блоке «подробности».

### Э8. Просмотр и правка `.xlsx` в браузере

Отдельный слой поверх результата: книга открывается в браузере, четыре листа
(«Свод по заказам», «Распределение 26 сч», «Расшифровка», «Счёт 26 (период)»),
вкладки листов, липкая шапка, `tabular-nums`.

- Читает и **сохраняет формулы и оформление** через `exceljs` — живые формулы
  файла интерфейс не ломает (ТЗ 5.1).
- Правка ячеек с явным различием: где было значение, где формула.
- Пересчёт методологии на клиенте не делается (ТЗ 4.2.3): файл сохраняется
  с флагом полного пересчёта при открытии, изменённые формульные ячейки
  помечаются как «пересчитает Excel».
- Сохранение — скачивание изменённой книги. Записи в 1С нет и не появится (ТЗ 4.2.1).

### Э9. С5 и С6 — Переопределение и история

- **С5:** снятие участия заказа в распределении 26 счёта, сравнение было/стало
  по долям и суммам CF, сброс одним действием, отсутствие переноса между периодами.
  Видно, какое состояние ушло в файл. На моках до появления ручки.
- **С6:** история расчётов (период, когда посчитан, результат, длительность,
  повторное скачивание), признак «из кэша» с датой исходного расчёта
  и принудительный пересчёт.

### Э10. Приёмка

Прогон по разделу 11 ТЗ на контрольном периоде **июнь 2026**: все формы ввода
периода, 27 групп и оборот 42 812 784,23, имя файла `Факт_управленка_2026-06.xlsx`,
совпадение сумм до копейки, отсутствие искажений округлением, экран несходимости,
разные сообщения при остановленном бэкенде и недоступной 1С, видимость `unmatched`,
появление новой колонки (44 сч) без правки кода таблиц.

## Что сознательно не делается

Запись в 1С, редактирование таблицы менеджеров, пересчёт методологии на клиенте,
плановый блок и ценообразование, мобильная версия, авторизация на текущем этапе
(ТЗ 4.2, 10.3).
