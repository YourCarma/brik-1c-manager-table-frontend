# Факт — фронтенд

Веб-интерфейс сервиса автоматического формирования блока «Факт» по заказам из 1С.
ТПК БРИК.

**Цель:** дать экономисту закрыть месяц целиком — посмотреть состав расчёта,
запустить расчёт, увидеть результат на экране, скачать `.xlsx` — не открывая
Swagger и не читая JSON.

## Стек

Vue 3 + TypeScript + Vite · Tailwind CSS 4 · Pinia · Vue Router ·
`decimal.js` (точность сумм) · `exceljs` (книга `.xlsx` в браузере).

Внешних CDN нет: шрифты, скрипты и стили поставляются вместе со сборкой —
в сети заказчика может не быть интернета (ТЗ 10.1). Шрифты только системные,
иконки и знаки рисуются самим CSS.

## Оформление

Визуальный слой нейтральный: серая шкала плюс один сдержанный акцент, статусы
отдельными ролями. Единственный источник токенов и примитивов —
[src/assets/ui.css](src/assets/ui.css); все классы имеют префикс `ui-`.
Локальных копий токенов и хардкода HEX в компонентах быть не должно.

Поддерживаются светлая и тёмная темы: те же роли-токены переопределяются под
`prefers-color-scheme` и под явный выбор `data-theme` на `<html>`. Переключатель
(`система → светлая → тёмная`) — в правой зоне шапки, выбор хранится
в `localStorage` под ключом `ui-theme`, атрибут ставится ещё в `index.html`,
до первой отрисовки. Любая правка оформления проверяется в обеих темах.

### Конфигурация

Адрес API задаётся переменной окружения, в код не зашивается (ТЗ 10.2).

| Переменная | Назначение |
|---|---|
| `VITE_API_BASE_URL` | Адрес сервиса. Пусто — тот же origin |
| `VITE_USE_MOCKS` | `true` — работа на моках без бэкенда |
| `VITE_REPORT_TIMEOUT_MINUTES` | Клиентский таймаут расчёта. По ТЗ 7.1.1 — не меньше 15 |
| `VITE_DEV_API_PROXY` | Только для разработки: цель прокси для `/api` и `/health` |

## Работа на моках

Часть методов бэкенда ещё не реализована (ТЗ 5.2): JSON-отчёт, фоновый режим,
история расчётов, переопределение участия. Интерфейс спроектирован под них сразу
и работает на моках; подмена мока на реальную ручку правится **в одном месте** —
`PENDING_ENDPOINTS` в [src/api/service.ts](src/api/service.ts) — и не требует
переписывания экранов.

Мок отвечает по-разному в зависимости от периода — так проходятся все состояния
из ТЗ 8 без тестового стенда:

| Период | Что показывает |
|---|---|
| `июнь 2026` | Контрольный период приёмки: 27 групп, оборот 42 812 784,23, всё сходится |
| `май 2026` | Пустой период: в 1С нет ни одной группы с оборотом |
| `апрель 2026` | Расчёт не сошёлся — экран С4 с перечнем проверок |
| `март 2026` | Несопоставленные группы и оборот без номенклатурной группы |
| `06.26`, `2026-13` | Отказ разбора периода с сообщением сервера |

## Правила, которые нельзя нарушать

Это не стиль, а требования ТЗ. Нарушение — дефект, а не предмет обсуждения.

1. **Суммы приходят строками и через `parseFloat`/`Number` не прогоняются** —
   ни для показа, ни для сортировки, ни для сравнения (ТЗ 5.3.1). Форматирование
   и сравнение — только через [src/lib/money.ts](src/lib/money.ts).
2. **Ноль показывается как `0,00`.** Пустая ячейка означает «нет данных» (ТЗ 5.3.2).
3. **Разбор периода — обязанность бэкенда.** Регулярок проверки ввода на клиенте
   нет (ТЗ 5.3.3).
4. **Методология не считается на клиенте:** ни итогов таблиц, ни процентов
   распределения, ни CC+CD+CE, ни формул книги (ТЗ 4.2.3).
5. **Колонки строятся по фактическим ключам `by_column`**, а не по захардкоженному
   списку. Словарь названий — [src/lib/columns.ts](src/lib/columns.ts) (ТЗ 5.2).
6. **Автоповторов тяжёлых запросов нет**, одновременно к сервису идёт не более
   одного (ТЗ 7.1.3, 7.1.4). За этим следит
   [src/api/heavyGate.ts](src/api/heavyGate.ts).
7. **Клиентский таймаут расчёта — не меньше 15 минут** (ТЗ 7.1.1).
8. **Кнопки «скачать всё равно» на экране несходимости не существует** (ТЗ С4).
9. **Никаких записей в 1С** — включая экран правки книги (ТЗ 4.2.1).
10. **«В работе» и «участвует в распределении 26 сч» — разные признаки** и никогда
    не смешиваются (ТЗ 3).

## Приёмка

`npm run check` закрывает автоматически проверяемую часть раздела 11 ТЗ:
контрольные суммы июня 2026, формат и точность сумм, терпимость таблиц
к новой колонке, имя файла из `Content-Disposition`, живые формулы книги.

Руками проверяются экранные критерии:

| Критерий | Как проверить |
|---|---|
| 11.1 Все формы ввода периода | Ввести `2026-06`, `06.2026`, `6/2026`, `июнь 2026`, `June 2026` — результат один. `06.26` и `2026-13` отклоняются с понятным сообщением |
| 11.6 Экран несходимости | Период `апрель 2026`, запустить расчёт: перечень проверок, кнопки скачивания нет |
| 11.7 Разные сообщения | Остановленный бэкенд → «Сервис «Факт» не отвечает», индикатор в шапке переходит в «недоступен». 502/504 → «Учётная система…», индикатор остаётся в «доступен»: наш сервис жив, проблема в базе |
